## 一、项目整体工程结构（Monorepo）
项目采用 **Monorepo 单仓库多项目结构**。
特点：
- 一个 Git 仓库
- 包含多个应用（apps）
- 包含多个共享库（packages）
- 前后端统一管理

### 推荐目录结构
```shell
limber-platform/  
│  
│─ apps/                     # 所有应用  
│  
│  ├─ platform-admin/        # 总平台前端  
│  ├─ company-admin/         # 企业管理后台前端  
│  ├─ employee-portal/       # 员工工作平台前端  
│  └─ backend/               # FastAPI 后端服务  
│  
├─ packages/                 # 共享代码  
│  
│  ├─ ui/                    # 共享 React UI组件  
│  ├─ types/                 # 共享 TypeScript 类型  
│  ├─ api-client/            # API SDK  
│  ├─ utils/                 # 通用工具函数  
│  └─ auth/                  # 登录与权限逻辑  
│  
├─ infra/                    # 部署相关  
│  ├─ docker/  
│  └─ compose/  
│  
├─ scripts/                  # 开发脚本  
│  
├─ pnpm-workspace.yaml       # workspace配置  
└─ package.json
```

说明：
- `apps`：所有应用
- `packages`：共享模块
- `infra`：部署配置
- `scripts`：自动化脚本

这种结构属于 **现代全栈 Monorepo 架构**。

## 四、后端工程架构 

### 后端技术栈
- **Python**：后端主要开发语言
    
- **FastAPI**：Web 框架，提供 REST API 与 WebSocket 能力
    
- **SQLAlchemy 2.0**：ORM 框架，用于数据模型定义与数据库访问
    
- **PostgreSQL**：核心业务数据库
    
- **Redis**：缓存、在线状态与实时能力支撑
    
- **JWT**：用于认证与登录态管理
    
- **PyCasbin**：用于权限模型执行与访问控制校验
    
- **structlog**：用于结构化日志输出
    
- **asgi-correlation-id**：用于注入请求级 `request_id`，便于问题排查与链路追踪


架构模式：

> **模块化单体（Modular Monolith）**

原因：

- 系统模块多
    
- 业务耦合高
    
- 个人开发
    

不适合一开始微服务。

# 九、总结

该项目采用：

> **Monorepo 全栈工程结构 + React 多应用架构 + FastAPI 模块化单体后端 + PostgreSQL 数据存储 + Redis 实时能力。**

开发策略：

> **优先实现员工端 MVP，再逐步补企业后台与 SaaS 管理平台。**
