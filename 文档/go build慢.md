## 回答2：
这是个很有意思也非常“反直觉”的现象。表面上看，-p 1 表示「只允许一个编译任务并行」，按理说应该更慢，但你却观察到它 “更快”。这其实是可能的，原因和你所处的系统环境、磁盘、杀毒软件等息息相关。

🧠 可能的真实原因如下：
1️⃣ Windows + 杀毒软件导致并行变慢
在 Windows 系统上，像 Windows Defender、360、火绒等杀毒软件会扫描每一个编译输出的 .obj、.a、.exe 文件。

当你设定 -p 比较大时（比如默认是 8 核），会同时生成多个中间文件，杀毒软件也会同时多线程介入干扰扫描，导致磁盘 I/O 爆炸性变慢。

而 -p 1 就只会一次处理一个编译任务，减少了同时文件创建/写入的数量，杀毒干扰也少，反而更快。

✅ 这种情况在 机械硬盘 和 开启了实时防护的系统 上尤其明显。

2️⃣ 高并发编译导致磁盘 IO 饱和
Go 编译过程中会创建大量临时文件（在 %TEMP% 路径下）

多个编译任务同时写临时文件 → 磁盘拥堵，特别是：

在老旧机械硬盘

或同时运行很多后台程序（例如编译器 + IDE + 杀毒 + OneDrive）

3️⃣ Go 项目较小，并发反而浪费调度开销
如果你的项目比较小、依赖少、文件少，调度多个编译进程反而带来上下文切换等调度成本。

-p 1 的串行编译反而让流程更简洁，执行路径更清晰。

🔍 举个例子：
并发 8 线程（默认）时：
go build -p 8 main.go

编译时间：5.2 秒

CPU 使用率高，磁盘峰值高，杀毒干扰大

串行 1 线程：
go build -p 1 main.go

编译时间：2.1 秒

CPU 利用率低，磁盘压力小，杀毒干扰少

✅ 建议解决方案
如果你经常遇到这种情况：

方法	描述
1. 使用 -p 1 或较低值	尽管牺牲并发，但更稳定
2. 给 Go 缓存目录、%TEMP% 加入杀毒软件白名单	避免 IO 卡顿
3. 使用 SSD 磁盘（尤其是开发目录和 temp 目录）	提高 IO 性能
4. 使用 go build + ./a.exe 代替 go run	更好控制流程，避免重复编译
