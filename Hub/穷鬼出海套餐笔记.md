## 1. 什么是"穷鬼出海套餐"

X（推特）独立开发圈流传的概念：**面向个人开发者 / 极小团队的"低预算甚至零预算"出海工具栈组合**。

- 目标人群：独立开发者（Indie Hacker）、1~3 人小团队、预算 < $100/月
- 核心诉求：把网站 / SaaS / 数字产品做出来并上线到全球市场
- 关键原则：
  - 能用免费层（Free Tier）就用免费层
  - 用 PaaS 而不是 IaaS，省运维
  - 优先选"按用量付费"的模型，避免月费陷阱
  - 工具栈尽量收敛，工具之间要能打通

## 2. 套餐工具栈总览

原 `文档/穷鬼出海套餐.md` 中的截图展示了 **套餐 1** 与 **套餐 2** 两套组合，下面是基于截图整理的可读清单（具体工具以原图为准，链接形式保留）。

### 2.1 套餐 1（典型结构）

| 环节 | 常见工具 | 免费层能力 |
|---|---|---|
| **域名** | Cloudflare Registrar / Namecheap / Porkbun | 首年 $1~$10 |
| **前端托管** | Vercel / Netlify / Cloudflare Pages | 静态站 + Serverless 完全免费 |
| **后端 / API** | Vercel Functions / Cloudflare Workers / Supabase | 月 100k~1M 次调用免费 |
| **数据库** | Supabase / Neon / PlanetScale / Turso | 500MB~几 GB 免费 |
| **认证** | Clerk / Supabase Auth / NextAuth | 月活 10k 以下免费 |
| **支付** | Stripe / Lemon Squeezy / Paddle | 按交易抽佣，无月费 |
| **邮件** | Resend / SendGrid / Postmark | 月 3k~100k 封免费 |
| **存储** | Cloudflare R2 / AWS S3 / UploadThing | R2 无出流费 |

### 2.2 套餐 2（典型结构）

套餐 2 通常在套餐 1 基础上做**场景化替换**：

- 把 Vercel 换成 **Cloudflare Pages + Workers**（进一步压成本）
- 把 Supabase 换成 **Turso / Neon**（更便宜或边缘计算友好）
- 加入 **Plausible / Umami**（自托管 / 免费层隐私分析，替代 Google Analytics）
- 加入 **Sentry**（错误监控，免费层够用）

## 3. Vercel 免费部署重点

原 `文档/穷鬼出海套餐.md` 末尾附了一个 B 站保姆级教程：[【保姆级教程】Vercel 免费部署网站](https://www.bilibili.com/video/BV1i7yUB3EJi/)。

下面是**教程核心步骤 + 后期重点**的提炼。

### 3.1 Vercel 适合什么

- ✅ Next.js / Nuxt / Astro / SvelteKit 等现代框架
- ✅ 纯静态站点（任何 SSG 工具）
- ✅ 轻量 API（Serverless Functions，单次 < 10s）
- ❌ 长任务 / 大文件处理（用 Cloudflare Workers 或独立服务器）
- ❌ 需要常驻进程的服务（用 Railway / Fly.io）

### 3.2 免费层额度（持续更新中）

| 项目 | Hobby 免费额度 |
|---|---|
| 部署次数 | 每天 100 次 |
| Serverless 执行时间 | 每月 100 GB-Hours |
| 出站流量 | 每月 100 GB |
| Functions 单次超时 | 10s（Hobby）/ 60s（Pro） |
| 团队成员 | 1 人 |

> 免费额度对个人项目 / 小流量 MVP 绰绰有余，量起来再考虑升级。

### 3.3 核心流程速记

1. **登录**：GitHub 账号授权
2. **导入仓库**：选 GitHub repo → 自动识别框架
3. **配置环境变量**：`Settings → Environment Variables`（生产 / 预览 / 开发三套）
4. **绑定域名**：`Settings → Domains`，Cloudflare 托管的域名按提示加 CNAME
5. **自动部署**：push 到 main → 自动生产部署；PR → 自动预览部署

### 3.4 后期重点学习清单

原 `文档/穷鬼出海套餐.md` 末尾留了一句"vercel 后期重点学习"，下面是系统化的学习路径：

#### 入门必学

- [ ] **环境变量管理**：`.env.local` 与 Vercel Dashboard 的同步、`@vercel/env` 类型提示
- [ ] **预览部署（Preview Deployments）**：每个 PR 自动生成 URL，给客户 / 团队 review
- [ ] **自定义域名 + HTTPS**：Cloudflare DNS 配置、SSL 自动签发
- [ ] **构建缓存**：`vercel.json` 配 `buildCommand` / `installCommand` 提速

#### 进阶

- [ ] **Edge Functions vs Serverless Functions**
  - Edge：基于 V8 边缘运行时，全球低延迟，不能用 Node API
  - Serverless：Node 运行时，功能全，延迟稍高
  - 选型：地理敏感 / 小逻辑 → Edge；需要 Node 生态 → Serverless
- [ ] **ISR（Incremental Static Regeneration）**：Next.js 按需重新生成静态页，省流量省时间
- [ ] **Image Optimization**：`next/image` 自动走 Vercel 图片 CDN
- [ ] **Cron Jobs**：`vercel.json` 配 `crons` 字段，定时触发 API

#### 生产化

- [ ] **监控与日志**：Vercel Analytics + 自带日志 + 第三方（Sentry / LogRocket）
- [ ] **错误追踪**：前端 `Sentry` SDK + API 端 Sentry 接入
- [ ] **限流与防护**：Vercel 自带 DDoS 保护 + 自定义 middleware 限流
- [ ] **CI/CD 进阶**：GitHub Actions 跑测试 → 通过后再让 Vercel 部署

## 4. 落地步骤建议

如果你要按"穷鬼套餐"实际做一个出海项目，按下面顺序走：

1. **明确产品**（这是 80% 失败的环节）：一个英文 Landing Page + 一个付费点
2. **搭站**
   - Next.js + Tailwind + shadcn/ui 起手
   - Vercel 一键部署，绑定 Cloudflare 域名
3. **接支付**
   - Stripe（信用卡，覆盖广）/ Lemon Squeezy（不开公司也能收美元）
4. **接数据库**
   - Supabase（Postgres + Auth + Storage 一站式）/ Neon（纯 serverless Postgres）
5. **接邮件**
   - Resend（开发者友好）/ Loops（营销自动化）
6. **接分析**
   - Plausible（隐私合规，月 $9 或自托管）或 Umami（免费自托管）
7. **上线 MVP**，验证付费转化，**再考虑**升级 Pro / 换工具栈

## 5. 注意事项

- **免费层 ≠ 永远免费**：超额度会被暂停服务或自动扣费，务必设账单告警
- **冷启动**：Serverless 闲置后会冷启动，首请求 1~3s，体验可接受但要心理预期
- **数据合规**：出海到欧盟要 GDPR，cookie banner / 隐私政策 / 数据删除接口不可省
- **域名风险**：被墙域名 / 商标问题提前排查，主备两套域名常备
- **心态**：套餐是工具栈清单，不是"用了就成功"——**产品本身才是核心**
