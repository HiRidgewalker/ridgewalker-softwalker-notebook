# 直面需求编写笔记

## 规则

本仓库是记录 software technology 的个人技术笔记本。当用户提出想记录一个技术栈、学习一个技术组件或编写一篇技术文章时，直接面向该需求，基于对应技术组件编写完整的学习文档笔记，而不是逐步向用户追问大纲、素材和章节划分。

用户给出的技术名即写作对象；用户补充的偏好（侧重点、深度、场景）直接融入笔记，缺口信息按其他笔记规则用合理默认值补齐。

## 原因

- 用户带着明确对象来（「我想学 Redis」），追问大纲只是把写作负担转移回用户
- 笔记规则已定义结构与取舍标准，缺省情况下 agent 可以独立产出合格笔记
- 产出后用户在成品上提修改意见，成本远低于事前来回问答

## 如何应用

- 识别用户意图是「记录技术 / 学习技术 / 写技术文章」后，直接开始产出笔记
- 对象模糊时（如「写点后端的东西」），一次性确认技术对象，确认后不再追问结构
- 用户明确要求先讨论方案或先列大纲时，按用户要求处理

## 示例

用户说「帮我写一篇 FastAPI 的笔记」，直接产出完整的 FastAPI 学习笔记（定位、安装、上手示例、常用特性、常见问题），而不是先反问「你想要哪些章节？侧重新手还是进阶？」
