# 代码规范与开发技巧笔记

> 本篇汇总日常开发中容易混淆或值得沉淀的两个基础主题：功能开关（Feature Flag）与序列化/反序列化。

---

## 1. 功能开关（Feature Flag）

### 1.1 什么是功能开关

功能开关是一种在**运行时**控制代码功能启用或禁用的机制，不需要重新部署代码就能打开或关闭某个功能。

它最常见的价值是提供一条「后悔药」：新功能上线后如果发现问题，可以立即关闭，而不是紧急回滚代码。

### 1.2 典型使用场景

| 场景 | 说明 |
|------|------|
| 灰度发布 | 先对 1% / 5% 用户开放新功能，观察指标后再全量 |
| A/B 测试 | 不同用户群体看到不同实现，对比转化率或体验 |
| 紧急止血 | 新功能出 bug 时，线上直接关闭，避免回滚 |
| 分支合并前置 | 未完成的功能代码先合入主干，但默认关闭，不影响主流程 |

### 1.3 简单实现方式

最常见的是基于**配置文件**或**环境变量**的布尔开关。

```python
import os

feature_flags = {
    "new_payment": os.environ.get("ENABLE_NEW_PAYMENT", "false").lower() == "true",
    "advanced_search": False,
}

def process_order(order):
    if feature_flags["new_payment"]:
        return process_payment_v2(order)
    return process_payment_v1(order)
```

### 1.4 使用注意事项

1. **开关应该有明确的Owner和清理时间**：避免临时开关变成永久代码债。
2. **默认关闭更安全**：新功能上线前默认关闭，通过配置逐步打开。
3. **与监控结合**：开关切换后要有指标反馈，否则无法判断影响。
4. **避免开关嵌套过深**：多层开关会让代码分支爆炸，难以测试。
5. **长期开关要平台化**：如果开关数量增多，应引入专门的功能开关平台（如 Unleash、LaunchDarkly），而不是散落在环境变量里。

## 2. 序列化与反序列化

### 2.1 基本概念

- **序列化（Serialization）**：把内存中的对象或数据结构转换成可存储、可传输的格式（字符串、字节流等）。
- **反序列化（Deserialization）**：把序列化后的数据还原成原始对象或数据结构。

### 2.2 常见序列化格式

| 格式 | 特点 | 典型场景 |
|------|------|----------|
| JSON | 文本、可读、跨语言 | Web API、配置文件、前端交互 |
| Protobuf | 二进制、体积小、速度快 | 微服务 RPC、移动端通信 |
| YAML | 文本、可读、支持注释 | 配置文件（Docker Compose、K8s） |
| XML | 文本、可读、结构严谨 | 企业级接口、旧系统对接 |
| Pickle | Python 专属二进制 | Python 进程间缓存、临时对象存储 |

### 2.3 Python 示例

#### 序列化

```python
import json

data = {"name": "Alice", "age": 25}
json_str = json.dumps(data, ensure_ascii=False)
print(json_str)
# 输出: {"name": "Alice", "age": 25}
```

#### 反序列化

```python
import json

json_str = '{"name": "Alice", "age": 25}'
data = json.loads(json_str)
print(data)
# 输出: {'name': 'Alice', 'age': 25}
```

> 注意：`json.dumps()` 返回字符串，`json.dump()` 是写入文件对象；`json.loads()` 从字符串解析，`json.load()` 从文件对象读取。

### 2.4 典型应用场景

1. **网络通信**：客户端与服务端通过 JSON / Protobuf 交换数据。
2. **持久化存储**：对象以 JSON / YAML 形式写入文件或数据库。
3. **远程调用**：RPC 框架把参数序列化后传输到远端执行。
4. **缓存**：对象序列化后存入 Redis，读取时再反序列化。

### 2.5 常见问题：__str__ / __repr__ 算序列化吗？

不算严格的序列化。

`__str__` 和 `__repr__` 生成的字符串主要是为了**人类可读**或调试，没有结构化、可解析的格式约定，通常也不能安全地还原为对象。

只有当类提供的方法能生成结构化格式（如 JSON、XML），并且这个格式用于**存储、传输或跨系统使用**时，才属于序列化。

```python
import json

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        # 调试用，不是序列化
        return f"Person(name={self.name}, age={self.age})"

    def to_json(self):
        # 自定义序列化
        return json.dumps({"name": self.name, "age": self.age}, ensure_ascii=False)
```

---

## 3. 小结

- 功能开关是控制发布风险的常用手段，但要有治理意识，防止变成永久开关。
- 序列化/反序列化是数据交换的基础，选型时要在可读性、体积、跨语言支持之间权衡。
- JSON 是 Web 开发中最通用的选择；Protobuf 适合高性能内部通信；Pickle 只应在受信任的 Python 进程内使用。
